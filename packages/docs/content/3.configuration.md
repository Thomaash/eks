# Configuration

`eks` needs an editor for two things:

- Editing the batch file in `--multiple` mode.
- Opening failure logs after a failed batch.

The same resolved editor is used for both.

## `--editor <executable>`

Override the editor for a single invocation:

```sh
eks --multiple --editor nvim
```

## Resolution precedence

`eks` picks the editor by trying, in order:

1. `--editor <executable>` flag
2. `$VISUAL` environment variable
3. `$EDITOR` environment variable
4. `nano` (fallback)

## Single-executable only

The editor name is passed directly to the OS as a single executable. Multi-word shell strings like `code --wait` are **not** supported — `eks` does not parse the value as a shell command. Use a plain executable name such as:

- `nvim`
- `vim`
- `nano`
- `code`
- `emacs`

If your preferred workflow needs flags, wrap them in a wrapper script on your `PATH` and pass that script's name to `--editor`.

## Skipping directories

When walking the project tree for `package.json` files, `eks` always skips a built-in set of directory basenames:

- `.git`
- `node_modules`
- `.pnpm-store`
- `.cache`
- `.output`
- `dist`

These defaults apply only to the `package.json` walker — `Makefile` and Deno-task discovery are unaffected. User input is **additive**: there is no way to un-skip a default.

### `--skip-dir <name>`

Add one literal directory basename to the skip set. The flag is repeatable; each occurrence contributes exactly one name. Values are **not** split on `:` or any other delimiter:

```sh
eks --skip-dir .idea --skip-dir tmp
```

### `EKS_SKIP_DIRS`

Colon-delimited list of basenames, PATH-style. Empty segments (from leading, trailing, or repeated colons) are dropped silently:

```sh
EKS_SKIP_DIRS=".idea:.venv" eks
```

### Composition

The effective skip set is the union of the built-in defaults, every `--skip-dir` occurrence, and every segment of `EKS_SKIP_DIRS`.

### Matching

Names are matched as literal directory basenames anywhere in the tree. Regex metacharacters in user values (e.g. `foo[1]`) are escaped automatically, so `--skip-dir .cache` does **not** also skip `Xcache`. Empty and whitespace-only values are discarded.
